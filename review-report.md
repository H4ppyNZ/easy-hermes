### Concurrency Reviewer (concurrency, resilience) — verdict: request changes

The cross-process race on `promotion_history.json` is **effectively closed in the main
flow**: load/update/save now sit inside
`atomic_io.file_lock(PROMOTION_HISTORY_PATH + ".lock")` (`select-models.py:1546-1591`),
and both save sites (`:1567`, `:1589`) are inside that block. `save_promotion_history`
itself remains lock-external, so safety depends on callers continuing to wrap it.

But broader shared state is unprotected:

- **blocker** — `select-models.py:1084`, `:1427-1433`,
  `hermes-ollama-selector.py:342-400` — `config.yaml` read-modify-write is unprotected
  across processes/entry points. Last writer wins; concurrent nightly/manual runs can
  revert promotions or drop fallback merges.
- **blocker** — `select-models.py:1465-1648` — the cache `file_lock` is acquired *before*
  probing and held through network I/O and the final config write. Concurrent
  `select-models.py` runs block up to 30s then raise `TimeoutError` instead of
  serializing cleanly.
- **major** — `select-models.py:394-412,1343,1354,1359` — `banned_models.json`
  load/save is unlocked; concurrent ban/unban or a selector run can lose updates.
- **major** — `select-models.py:1089` — backup written with `bak.write_text(...)`
  (truncates in place); crash leaves a corrupt recovery artifact.
- **major** — `hermes-ollama-selector.py:95-108,342-400` — reads and rewrites
  `config.yaml` without any lock; races with `select-models.py`.
- **major** — `poll_base.py:105-111`, `poll_gemini.py:643-663`,
  `poll_novita.py:521-527`, `poll_ollama_cloud.py:483-489`, `poll_nvidia.py:601-610`,
  `poll_openrouter.py:262-276` — poller outputs use `open(path, "w")` (non-atomic,
  unlocked); concurrent runs on the same path can tear the file.
- **minor** — `release_dates.py:9-25`, `select-models.py:532-559` — `_OR_MAP` /
  `_OR_CONTEXT_MAP` lazy init unsynchronized; threads can initialize twice and duplicate
  network fetches.
- **minor** — `select-models.py:57-63,126-131` — `save_last_selection` and
  `save_promotion_history` are lock-external; safe only when callers wrap them.
- **minor** — `atomic_io.py:21-56` — `file_lock` is not reentrant on the same file in
  one process (nested acquisition times out) and locks only a 1-byte region.
- **minor** — `Set-ModelSelectorTask.ps1:73` — `MultipleInstances IgnoreNew` prevents
  same-task overlap, but the nightly and selector tasks can still run concurrently;
  relies on the unprotected `config.yaml` write.

## Overall verdict: request changes

Top 3 blockers:

1. **Cross-process unprotected `config.yaml` RMW.** `write_config`, ranking-matrix writes, and
   `hermes-ollama-selector.py` all write `config.yaml` without a shared lock; last writer
   wins. Combined with the nightly (3 AM) and selector (4 AM) tasks both running, concurrent
   runs can revert promotions or drop fallback merges. *(Concurrency X2/X11)*
2. **Installer is broken.** `hermes-setup.ps1` resolves the deleted `hermes-model-selector.py`
   (URL, sibling filename, temp dest, probe pattern, messages); `Get-SelectorScript` throws
   on fresh/`irm | iex` installs. *(Architecture X1 + Maintainability)*
3. **Security boundary still bypassable.** `providers.validate_key` leaks the Gemini key into
   a query string; env guards accept `http://` and userinfo; `--base-url`/`--endpoint`/`--base`
   overrides bypass the guards entirely; installer executes unpinned remote code. *(Security)*

The refactor made real progress — `hermes-model-selector.py` is gone (single owner),
`release_dates.py` was extracted, `safe_url`/`atomic_io` were hardened, the broken
`hermes_ollama_selector` import now works via `importlib.util`, listing-only providers get
`clean_pass=False`, and pollers were partially deduped. But the cutover is incomplete: the
installer is broken, `hermes-ollama-selector.py` remains a second config writer, the
`ollama-local` registry entry still bypasses its own contract, and release-date resolution
(the gate's primary sort key) is still duplicated and divergent.

**Suggested order of work:**
1. X2 — share a `config.yaml.lock` across all writers (select-models + hermes-ollama-selector).
2. X1 — repoint `hermes-setup.ps1` at `select-models.py` (URL, sibling, temp dest, probe, messages).
3. X3 — `providers.validate_key` header form; require `https` + no userinfo in env guards;
   apply the same allowlist to `--base-url`/`--endpoint`/`--base`.
4. X4 — make `hermes-ollama-selector.py` catalog-only or delegate config writes.
5. X5 — move all release-date tables into `release_dates.py`; fix the local-time bug;
   correct the `stepfun` drift.
6. X10 — add a normally-importable `poll_ollama_local.py` (or rename) and remove the
   three `importlib.util` shims; fix `configured_providers` to honor explicit `--providers`.
7. X11 — narrow the cache lock to load/save only.
8. X6/X7/X8/X9 — atomic poller writes + `--out` containment; doc cleanup; capability
   tagging wiring; poller dedup + `poll_base` helpers.
