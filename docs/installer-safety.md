# easy-hermes installer -- blast radius and safe re-run order

Repo: `C:\Users\mattw\Documents\repos\easy-hermes` (git, `github.com/H4ppyNZ/easy-hermes`).
Files: `hermes-setup.ps1` (installer; params `-Yolo`, `-Model`, `-SkipInstall`, `-SkipDocs`,
`-SelectorOnly`, `-SchedulerOnly`, `-Update`, `-NoUpdate`), `select-models.py` (free-tier
probe + promotion gate, facade over `selector/`), `MANIFEST.json` (the file set the
installer syncs). The README one-liners use the scriptblock cast and pull `main`, so a push
is live for testers at once.

## Re-running `hermes-setup.ps1` -- worst case per step

| Step | Runs when | What it can do |
|---|---|---|
| auto-update | `-Yolo` or `-Update` | clone: `git fetch` + `merge --ff-only` (dirty tree skipped); one-liner: re-syncs `MANIFEST.json` files into `%LOCALAPPDATA%\hermes\easy-hermes` |
| install | default (not `-SkipInstall`) | downloads and runs the official `install.ps1`; **upgrades an existing Hermes checkout** |
| auth | always | no-op when already authenticated (`hermes auth list` matches the provider) |
| model | `-Model` given | `hermes config set model.default` |
| selector | `-Yolo`, `-SelectorOnly`, or answered yes | **rewrites `fallback_providers` + `agent.reasoning_overrides`**; can move `model.default` |
| connectors / ACP | guided mode only | prompts; no writes |
| verify | always | `hermes doctor`, read-only |

**The install step is the real risk, and it is not data loss.** `install.ps1` treats an
existing `$InstallDir` containing `.git` as "update me": fetch, then
`git reset --hard origin/<branch>` -- or move the tree aside to
`$InstallDir.broken-<yyyyMMdd-HHmmss>` when the clone has no commits. A plain re-run
silently upgrades Hermes to the latest `main`, refreshes the dependency environment
under the user, and stashes uncommitted changes before any reset.

**The selector merges into config.** `write_config()` in `select-models.py` MERGES new
fallback entries into the existing `fallback_providers` list (dedup by provider+model);
`model.default` may move via the promotion gate. If nothing passes probing it returns early
and leaves the config untouched. Writes go through ruamel's
`atomic_roundtrip_yaml_save`, so there is no half-written-config risk; the values churn, the
file never corrupts.

Promotion gate (`choose_default`): `PROMOTION_MARGIN = 2` consecutive clean passes,
hysteresis 7 days, `HISTORY_PRUNE_DAYS = 30`. The incumbent keeps the slot unless a
challenger is both eligible and strictly newer by the hysteresis window. An incumbent that
is in scope but FAILED this run's probe is the one case that triggers emergency promotion --
an incumbent that is merely absent from the free-model cache is "out of scope" and is never
displaced by that path.

Probe results vary run to run, so a re-run is not a no-op even when the gate keeps
`model.default`: the chain and the overrides still churn.

## Auto-update blast radius

Two shapes, resolved by `Resolve-ScriptBaseDir`:

- **clone** -- a git work tree sits next to `hermes-setup.ps1`. `-Yolo` fast-forwards it.
  A dirty tree, a missing upstream, or a failed fetch/merge all **skip with a warning**;
  local commits and uncommitted work are never rewritten. The commits pulled are printed.
- **one-liner** -- `$PSScriptRoot` is EMPTY under the scriptblock cast, so there is no
  sibling to read. `MANIFEST.json` is fetched and every file it lists is downloaded into
  `%LOCALAPPDATA%\hermes\easy-hermes`, compared by SHA256 (byte-safe for the non-ASCII in
  `select-models.py`), and moved into place only when different. A failed fetch keeps the
  existing copy. If `MANIFEST.json` itself cannot be fetched but the install dir
  already holds a `VERSION` file, that is a warning and the run continues -- so a
  re-run (including `-SchedulerOnly`, which needs no network) survives offline. A
  first install has no `VERSION`, so a missing manifest is still fatal there.
  `MANIFEST.json` is generated by `tools/gen_manifest.py`, which walks imports from
  `select-models.py`, the `providers.py` registry (those pollers are loaded with
  `importlib`, not imported), the pollers' own imports, and the explicit `EXTRA` /
  `EXTERNAL` lists. An import it cannot place on disk fails the run rather than
  shipping silently short.

Opt-out is sticky: `-NoUpdate` writes `%LOCALAPPDATA%\hermes\easy-hermes\NOUPDATE`, and
`EASY_HERMES_NO_UPDATE=1` is honoured too. `-Update` overrides the marker for that one run;
it does not override the env var. Delete the marker to clear it permanently.

## Safe order if a re-run is wanted

1. Back up the config: `cp config.yaml config.yaml.bak`.
2. `--dry-run` the selector first -- it probes and prints the would-be config, writing
   nothing. Verify that claim: `config.yaml`, `cache/promotion_history.json` and
   `cache/fallback_model_cache.json` mtimes must be unchanged afterwards.
3. `-SkipInstall` to leave the Hermes version alone; `-SelectorOnly` when only the probe is wanted.
4. Report which keys would change and to what, rather than "it should be fine".

## Scope of the writes

The selector targets `$HERMES_HOME` (default `%LOCALAPPDATA%\hermes`), i.e. the **default
profile's** `config.yaml`. Other profiles under `profiles/<name>/` are untouched unless
`HERMES_HOME` is pointed at one.

## Nightly extra tasks (`extra-tasks.ps1`)

`NightlyRestartTask.ps1` step 4 runs host-specific maintenance. That list lives
in `extra-tasks.ps1` next to the script, which is **gitignored and absent from
`MANIFEST.json`**: an install or auto-update never creates, overwrites, or deletes
it, and it is never pushed. One-liner installs read it from
`%LOCALAPPDATA%\hermes\easy-hermes\extra-tasks.ps1`.

Blast radius: the file is dot-sourced and its scriptblocks run as the
scheduled-task user at 3 AM, with that user's rights. Anything the file can do,
the nightly run can do. Keep it to data and scriptblocks, and never commit it.

Failure behaviour: a task whose literal script path is missing is skipped with a
log line; a task that throws is logged as an error and the run continues; a
config file that fails to parse is logged as an error. None of these abort the
nightly run, but the last two make the script exit `1`, which the Hermes cron
monitor reports. Schema and examples: `docs/nightly-restart.md`.

## Verifying an edit before pushing

- `.ps1`: clean parse under the Windows PowerShell 5.1 parser --
  `[System.Management.Automation.Language.Parser]::ParseFile($path, [ref]$null, [ref]$err)`
  with `$err` empty. pwsh 7 passing proves nothing about `iex`.
- `.py`: `py_compile` with the Hermes venv python.
- Keep `.ps1` source ASCII-only: `write_file` emits UTF-8 without a BOM and 5.1 decodes
  that as CP1252, mangling any multi-byte character into a string-terminating quote.
